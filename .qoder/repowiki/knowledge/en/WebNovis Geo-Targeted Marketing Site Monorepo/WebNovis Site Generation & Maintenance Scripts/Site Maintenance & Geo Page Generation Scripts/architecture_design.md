The module is a flat collection of executable Node.js/Python/PowerShell scripts plus two sub-packages. The `geo/` sub-package implements a structured, multi-phase CLI pipeline orchestrated by `main.js`: it reads shared configuration from `config.js` (CLI flags like `--dry-run`, `--validate-only`, `--type=`, `--city=`, `--service=`), loads city/service metadata from `data.js` (JSON sources in `data/cities.json`, `data/services.json` plus approved AI content blocks), renders HTML via Nunjucks templates in `templates/` using renderers (`render-agenzia.js`, `render-realizzazione.js`, `render-servizio.js`, `render-hubs.js`), validates output through `validate.js` and `schema.js`, finalizes paths via `paths.js`/`paths-core.js`, and writes published files to `PUBLISH_DIR`. Each generated page goes through a fixed pipeline: generate → finalize → validate (blocking on issues prefixed with ⛔) → write → log stats. A link graph is emitted to `REPORT_DIR/link-graph.json` and editorial dates are persisted to `data/geo-page-dates.json`. The `legacy/` directory holds older generators (`gen-geo-pages.js`, `gen-pillar-articles.js`, `generate-city-pages.js`) and a large set of disposable root-oneoff scripts (renamed `check*.js`, `fix*.py`, `update_*.py`) moved out of the repo root to avoid public exposure; these are not referenced by CI or package manifests and serve as historical migration utilities. Top-level scripts at `scripts/` are independent one-offs for SEO enrichment, footer normalization, form fixes, cache busting, LLM exports, and artifact preparation, each runnable directly via `node <script>.js`.
