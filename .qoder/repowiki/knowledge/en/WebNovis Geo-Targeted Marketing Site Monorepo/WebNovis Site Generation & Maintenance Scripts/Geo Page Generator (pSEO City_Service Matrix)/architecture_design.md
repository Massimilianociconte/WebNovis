Single-process Node.js script orchestrated by `main.js`, which reads shared configuration from `config.js` (CLI flags like `--type`, `--dry-run`, `--validate-only`, target city/service filters, publish/report directories) and data from `data.js` (JSON sources `data/cities.json`, `data/services.json`, approved AI content blocks via `content-claim-governance`). Four rendering modules produce the three page families plus hubs: `render-agenzia.js` (per-city agency pages), `render-realizzazione.js` (per-city realization pages), `render-servizio.js` (combinatorial service×city matrix), and `render-hubs.js` (internal linking hub pages). Each renderer follows the same pipeline: load a Rho base template via `paths-core.getBasePage`, build a Nunjucks context using `njkEnv.render('...-content.njk')`, inject head/nav/footer with `head-meta.updateDerivedHeadMeta`, generate JSON-LD via `schema.generateSchemas`, run `validate.validatePage`, then finalize through `paths.finalizePublishedHtml` and write to disk. Cross-cutting concerns are isolated in dedicated files: `faq.js` resolves hand-crafted or fallback FAQs, `editorial.js` applies per-path editorial overrides, `copy.js` provides SEO copy, `html-utils.js` supplies DOM helpers (`stripHtml`, `countWords`, `getNearestCities`), `link-graph.js` builds an internal link graph written as `link-graph.json`, `dates.js` persists `geo-page-dates.json` after successful writes, and `validate.js` enforces fail-closed checks (word count ≥300/500, ≥5 internal links, ≥3 JSON-LD blocks, canonical/H1 presence, unsupported claims). Dependency direction is strictly inward: renderers depend on config/data/utils/schema; nothing in this module is imported by application code — it is a self-contained generator consumed only by CI/build scripts.
