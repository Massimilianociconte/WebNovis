Two independent Cloudflare Workers deployed via Wrangler, each with its own `wrangler.jsonc` manifest and single-entry `src/index.js`:

- `webnovis-ai`: A stateful API worker exposing `/api/health`, `/api/chat`, `/api/search-ai`, and `/api/chat-lead`. Routing is centralized in the default `fetch` handler which dispatches by method+pathname. Business logic is split into three modules: `catalog.js` holds static pricing/contact data and keyword-based fallback responses; `search-engine.js` builds an in-memory corpus from `data/search-index.json` using token-based scoring, intent inference (`pricing|contact|portfolio|about|informational|local|commercial|general`), and produces both ranked results and Gemini prompts; `index.js` orchestrates session persistence (KV namespace `SESSIONS`), rate limiting (per-IP sliding buckets), prompt assembly, Gemini calls with primary/fallback model retry (`gemini-2.5-flash-lite` → `gemini-2.5-flash`), KV-backed search result caching, and fire-and-forget Brevo email notifications for leads.
- `webnovis-forms`: A thin proxy worker at `/submit` that validates Cloudflare Turnstile tokens server-side (with hostname and action allowlists), applies a honeypot field (`botcheck`), then forwards the form as `FormData` to `WEB3FORMS_ENDPOINT` (defaulting to Web3Forms). It supports JSON or form-encoded input and returns normalized `{success,message}` responses.

Dependency direction is one-way: `index.js` imports from `catalog.js` and `search-engine.js`; no cross-worker communication. Both workers rely on environment secrets/vars injected by Wrangler rather than hard-coded credentials.
